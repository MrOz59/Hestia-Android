# Configure Android signing entirely in the GitHub website

This procedure works from a phone browser. No PC, terminal, Android SDK or
pre-existing keystore is needed.

## 1. Create a temporary token

Open [New fine-grained personal access token](https://github.com/settings/personal-access-tokens/new).

- Name: `Hestia signing setup`.
- Resource owner: `MrOz59`.
- Expiration: one day (or another short expiration).
- Repository access: **Only select repositories**, then **Hestia-Android**.
- Repository permissions: **Secrets → Read and write**. Metadata read access
  is automatically included. No Contents write or broad classic `repo` token is
  needed.

Generate and copy the token. Paste it only into the repository Secret below.

## 2. Add two repository Secrets

Open [Hestia Android Actions Secrets](https://github.com/MrOz59/Hestia-Android/settings/secrets/actions).
Use **New repository secret** for each entry:

| Name | Value |
| --- | --- |
| `HESTIA_SIGNING_SETUP_TOKEN` | The temporary fine-grained token from step 1. |
| `HESTIA_SIGNING_BACKUP_PASSWORD` | A unique password of at least 32 characters, saved in your password manager. This encrypts the private signing backup. |

The keystore is generated by the workflow, so you do not need to paste a key or
manually prepare the four `HESTIA_NIGHTLY_*` values.

## 3. Run the setup button

Open [Set up Android signing from the browser](https://github.com/MrOz59/Hestia-Android/actions/workflows/setup-android-signing.yml).

1. Select **Run workflow**.
2. Use branch **moonlight-noir**.
3. Leave **restore_run_id** at **0** for first setup.
4. Press **Run workflow**.

The workflow tests the tools, generates an RSA signing identity, uploads an
AES-256 encrypted backup, configures the four permanent signing Secrets, and
starts the Android RC2 build. It removes the temporary setup-token Secret on
success. It does not print private keys/passwords or publish an unencrypted key.
The usual RC build, tests and APK checks still gate publication.

## 4. Keep the backup

Open the successful setup run and download its **hestia-signing-backup-RUN_ID**
artifact. Save it on your phone or your own storage and keep the backup password.
The artifact expires after 90 days; the permanent signing Secrets remain in the
repository. Revoke the temporary personal access token in your GitHub settings
after setup finishes.

The encrypted file contains the original PKCS12 key and its credentials. When a
PC is available, decrypt with GnuPG or use `scripts/signing-backup.py decrypt`.
The permanent signing key must be reused for future in-place APK updates.

## Recovery after a partial failure

The encrypted backup is uploaded before any signing Secret is written. If only
some of the four signing Secrets were created, start a **new** setup run with
**restore_run_id** set to the previous run's numeric ID (from its Actions URL).
Keep the same backup-password Secret. The workflow downloads and decrypts that
original backup and completes setup with the same key. It accepts recovery only
from a manual setup run on this repository's default branch.

If all four permanent Secrets already exist, setup refuses to generate another
key. Run [Hestia Android Nightly](https://github.com/MrOz59/Hestia-Android/actions/workflows/nightly.yml)
manually with branch **release/october-2026-rc2** instead. This also handles the
case where signing setup succeeded but dispatching the RC build failed.

For existing-key setup and the one-time RC1 certificate transition, see
[Android signing](android-signing.md). The Play Protect report remains separate
from verifying the signing setup.
